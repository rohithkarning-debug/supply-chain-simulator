### 3.2 Stakeholders and Concerns

The Supply Chain Management Simulator addresses the operational, educational, and architectural concerns of four key stakeholder roles:

| Stakeholder | Role in Project | Primary Architectural Concerns | Architectural Solutions & Mitigations |
| :--- | :--- | :--- | :--- |
| **Supply Chain Analyst** | Primary end user configuring scenarios and evaluating operational performance | - High-fidelity detection and reporting of delays, stockouts, back-orders, and excess inventory.<br>- Deterministic simulation reproducibility so that identical configurations yield identical results.<br>- Intuitive, clean command-line reporting without noisy stack traces. | - Analytics module (`scm_sim.analytics`) produces structured report dictionaries and formatted summaries with explicit counts and "No issues" indicators.<br>- Dependency injection of seeded pseudorandom number generators (`random.Random(seed)`) ensures run-to-run determinism.<br>- Clear CLI output streaming daily logs and final multi-line summary. |
| **Course Instructor / Evaluator** | Academic evaluator assessing software quality, compliance, and functionality | - Ability to execute demo scenarios with a single CLI command.<br>- Thorough, automated test coverage (>= 90%) validating all requirements.<br>- Clean software engineering documentation following IEEE standards. | - Module execution entry point (`python -m scm_sim --days 10 --seed 42`) runs pre-configured realistic scenario (`build_demo()`) in < 1 second.<br>- Comprehensive pytest test suite (73 automated tests, 97% line coverage) executed on every commit via GitHub Actions CI.<br>- Traceable SRS, SAD, and Test Plan mapped to requirements and automated test cases. |
| **Module Developers (Team Members)** | Software engineers building and maintaining subsystem modules in parallel | - Strong module decoupling and encapsulation to prevent cross-module interference.<br>- Clear, documented public APIs with well-defined parameter types and exception guarantees.<br>- Fast, reliable local unit test execution without external services or network setup. | - Layered modular architecture: each developer owns an isolated module (`inventory.py`, `orders.py`, `shipments.py`, `analytics.py`).<br>- Strict in-memory operation using only the Python standard library and pytest.<br>- Invariant enforcement: operations fail fast and leave state completely unchanged on error. |
| **Team Lead / Integration Owner** | Integrator combining modules into cohesive simulation orchestrator | - Seamless integration of independently developed modules into the daily simulation loop.<br>- Prevention of merge conflicts and regression errors.<br>- Transparent commit history and pull request accountability. | - Simulation facade (`scm_sim.simulator.Simulation`) orchestrates daily execution sequence in a fixed order.<br>- GitHub branch protection on `main` enforcing PR reviews, green CI checks, and linear git history. |
