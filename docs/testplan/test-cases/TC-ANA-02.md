| **TC ID** | TC-ANA-02 |
| **Title** | Order Metrics, Fill Rate, Daily Report Composition and Report Formatting |
| **Requirement(s)** | SCM-F-032, SCM-F-033 |
| **Type** | Functional |
| **Objective** | Verify that `order_metrics` counts orders per status and computes the fill rate exactly as specified, including when the denominator would be zero and when statuses are supplied as enumeration members, as strings or as a mixture, and that `build_report` and `format_report` produce a complete daily report and a readable text rendering in which empty sections print "No issues". |
| **Preconditions** | The `scm_sim` package is importable. Orders are supplied as stand-ins exposing `status` only; no `OrderManager` instance is required. The `orders` sub-dictionary of the report is produced by `order_metrics`, so `format_report` receives exactly the keys `build_report` guarantees. |
| **Test data** | Five orders with statuses PENDING, FULFILLED, FULFILLED, BACKORDERED, CANCELLED. Four orders with statuses FULFILLED, FULFILLED, PENDING, CANCELLED. One order with status `OrderStatus.FULFILLED` and one with the plain string `"FULFILLED"`. An empty order list. Report fixture: stock `{("WH-NORTH","WIDGET"): 0, ("WH-NORTH","GADGET"): 5, ("WH-SOUTH","GIZMO"): 600}`, one in-transit shipment expected on day 5, two orders FULFILLED and PENDING, `current_day = 8`. Empty report fixture: empty stock, no shipments, no orders, `current_day = 1`. |
| **Steps** | 1. Call `order_metrics` on the five-order list and inspect `total`, `pending`, `fulfilled`, `backordered`, `cancelled`.<br>2. Call `order_metrics` on the four-order list and inspect `fill_rate`.<br>3. Call `order_metrics` on the empty list and inspect `total` and `fill_rate`.<br>4. Call `order_metrics` on the list mixing an `OrderStatus` member with a plain string status and inspect `fulfilled`.<br>5. Call `build_report(stock, shipments, orders, current_day=8)` and inspect the key set, `day`, and each sub-result.<br>6. Call `build_report` with `reorder_point=60, max_level=40` and confirm the thresholds are forwarded.<br>7. Call `format_report` on the report from step 5 and inspect the header and section headers.<br>8. Call `format_report` on the empty report from step 5 and count the occurrences of `No issues`. |
| **Expected result** | 1. `total = 5`, `pending = 1`, `fulfilled = 2`, `backordered = 1`, `cancelled = 1`.<br>2. `fill_rate = 0.67`, i.e. $\text{round}(2 \div (4 − 1), 2)$ — the cancelled order is excluded from the denominator.<br>3. `total = 0` and `fill_rate = 0.0`, with no `ZeroDivisionError`.<br>4. `fulfilled = 2`, proving both status representations are recognised.<br>5. The key set is exactly `{day, delayed_shipments, stockouts, low_stock, excess, orders}`; `day = 8`; `stockouts = [("WH-NORTH","WIDGET")]`; `low_stock = [("WH-NORTH","GADGET",5)]`; `excess = [("WH-SOUTH","GIZMO",600,100)]`; the in-transit shipment is 3 days late; `orders["fill_rate"] = 0.5`.<br>6. A quantity of 50 is reported as low stock at `reorder_point = 60` and as excess with surplus 10 at `max_level = 40`.<br>7. The text contains `Day 8`, `Delayed shipments (1)`, `Stockouts (1)`, `Low stock (1)`, `Excess (1)` and `Orders (2)`, and one `  - ` line per item.<br>8. The text contains `Delayed shipments (0)` and the string `No issues` exactly 4 times — once for each of the four empty sections. |
| **Pass/fail criteria** | **Pass** if all six listed pytest tests pass, i.e. every status count is correct, the fill rate is `fulfilled ÷ (total − cancelled)` rounded to 2 decimal places, it is 0.0 whenever the denominator is not positive, mixed enum and string statuses are accepted, `build_report` returns exactly the six specified keys and forwards the thresholds, and `format_report` prints a counted section per key with `No issues` for each empty section. **Fail** if a cancelled order is counted in the fill-rate denominator, if `ZeroDivisionError` is raised for an empty or fully cancelled order list, if a report key is missing or unexpected, if a caller-supplied threshold is ignored, or if any empty section omits the `No issues` marker. |
