| **Title** | Delayed-Shipment Detection and Inventory Exception Classification |
| **Requirement(s)** | SCM-F-030, SCM-F-031 |
| **Type** | Functional |
| **Objective** | Verify that `find_delayed_shipments` reports only shipments that are genuinely late, computes `days_late` from the correct reference day, and orders the worst delays first, and that `find_stockouts`, `find_low_stock` and `find_excess` partition the stock snapshot correctly at their exact boundary values. |
| **Preconditions** | The `scm_sim` package is importable (`PYTHONPATH=src` or run from `src/`). No simulation, `Inventory`, `ShipmentManager` or `OrderManager` instance is required: the Analytics functions read plain data and hold no state. |
| **Test data** | Shipments built as stand-ins exposing `shipment_id`, `sku`, `warehouse_id`, `expected_day`, `actual_day`: `SHP-0001` expected day 5 in transit; `SHP-0001` expected day 5 delivered day 7; `SHP-0001` delivered day 5 (on time); `SHP-0002` delivered day 3 (early); two shipments 1 and 4 days late. Stock snapshot `{("WH-NORTH","WIDGET"): 0, ("WH-NORTH","GADGET"): 1, ("WH-NORTH","GIZMO"): 20, ("WH-NORTH","BOLT"): 21, ("WH-SOUTH","WIDGET"): 500, ("WH-SOUTH","GADGET"): 501, ("WH-SOUTH","GIZMO"): 0}` with default thresholds `reorder_point = 20` and `max_level = 500`. |
| **Steps** | 1. Call `find_delayed_shipments([shipment], current_day=8)` for the shipment expected on day 5 and still in transit; inspect `days_late`.<br>2. Call `find_delayed_shipments([shipment], current_day=20)` for the same shipment delivered on day 7; inspect `days_late`.<br>3. Call `find_delayed_shipments` on the on-time (day 5) and early (day 3) shipments at `current_day = 10`.<br>4. Call `find_delayed_shipments` on two shipments 1 and 4 days late at `current_day = 10`; inspect the order of `shipment_id` in the result.<br>5. Call `find_stockouts(stock)`, `find_low_stock(stock)` and `find_excess(stock)` on the stock snapshot with default thresholds; compare each result against the expected tuples.<br>6. Call `find_low_stock(stock, reorder_point=21)` and `find_excess(stock, max_level=100)` to confirm the thresholds are applied per call. |
| **Expected result** | 1. `days_late = 3` for the in-transit shipment, computed as `current_day 8 − expected_day 5`.<br>2. `days_late = 2`, computed from the recorded `actual_day 7` and **not** from `current_day 20`.<br>3. An empty list: neither shipment is late.<br>4. The result is ordered worst first, so `SHP-0002` (4 days late) precedes the 1-day-late shipment.<br>5. `find_stockouts` returns exactly `[("WH-NORTH","WIDGET"), ("WH-SOUTH","GIZMO")]` — only the two zero-quantity items, sorted. `find_low_stock` returns exactly `[("WH-NORTH","GADGET",1), ("WH-NORTH","GIZMO",20)]` — 0 excluded, 20 included, 21 excluded. `find_excess` returns exactly `[("WH-SOUTH","GADGET",501,1)]` — 500 excluded, 501 included, surplus 1.<br>6. `reorder_point = 21` additionally reports `("WH-NORTH","BOLT",21)`; `max_level = 100` reports the surplus as `qty − 100`. |
| **Pass/fail criteria** | **Pass** if all seven listed pytest tests pass, i.e. `days_late` uses `actual_day` when delivered and `current_day` otherwise, only `days_late > 0` is reported, the ordering is descending with the two stock classifiers producing exactly the boundary results above, and caller-supplied thresholds override the defaults. **Fail** if any shipment at or before its expected day is reported, if a delivered shipment's lateness is computed from the current day, if the ordering is ascending or unsorted, if a quantity of 0 is classified as low stock, if 21 appears under the default reorder point, if 500 is classified as excess, or if any of the three lists is unsorted. |
