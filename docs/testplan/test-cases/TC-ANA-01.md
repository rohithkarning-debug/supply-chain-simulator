| **Title** | Delayed-Shipment Detection and Inventory Exception Classification |
| **Requirement(s)** | SCM-F-030, SCM-F-031 |
| **Type** | Functional |
| **Objective** | Verify that `find_delayed_shipments` reports only shipments that are genuinely late, computes `days_late` from the correct reference day, and orders the worst delays first; and that `find_stockouts`, `find_low_stock` and `find_excess` partition the stock snapshot correctly at their exact boundary values, using each item's own stock policy thresholds with 20/500 as the global fallback. |
| **Preconditions** | The `scm_sim` package is installed (`pip install -e .`) or importable via `PYTHONPATH=src`. No simulation, `Inventory`, `ShipmentManager` or `OrderManager` instance is required for steps 1–7: the Analytics functions read plain data and hold no state. Step 8 uses a `Simulation`. |
| **Test data** | Shipments built as stand-ins exposing `shipment_id`, `sku`, `warehouse_id`, `expected_day`, `actual_day`. Stock snapshot with items having custom `StockPolicy` (e.g. `reorder_point=50, max_level=200`, `reorder_point=10, max_level=30`) and items without policies falling back to `reorder_point=20` and `max_level=500`. |
| **Steps** | 1. Call `find_delayed_shipments([shipment], current_day=8)` for the shipment expected on day 5 and still in transit; inspect `days_late`.<br>2. Call `find_delayed_shipments([shipment], current_day=20)` for the same shipment delivered on day 7; inspect `days_late`.<br>3. Call `find_delayed_shipments` on the on-time (day 5) and early (day 3) shipments at `current_day = 10`.<br>4. Call `find_delayed_shipments` on two shipments 1 and 4 days late at `current_day = 10`; inspect the order of `shipment_id` in the result.<br>5. Call `find_stockouts(stock)`, `find_low_stock(stock)` and `find_excess(stock)` on the stock snapshot with default thresholds; compare each result against the expected tuples.<br>6. Call `find_low_stock(stock, reorder_point=21)` and `find_excess(stock, max_level=100)` to confirm the thresholds are applied per call.<br>7. Call `find_low_stock` and `find_excess` on items with custom policies; verify that each item's own `reorder_point` and `max_level` determine alerts.<br>8. Verify in a `Simulation` that daily report alerts evaluate using per-item policy thresholds. |
| **Expected result** | 1. `days_late = 3` for the in-transit shipment, computed as `current_day 8 − expected_day 5`.<br>2. `days_late = 2`, computed from the recorded `actual_day 7` and **not** from `current_day 20`.<br>3. An empty list: neither shipment is late.<br>4. The result is ordered worst first.<br>5. Boundary values 0, 20, 500 evaluate strictly per specification.<br>6. Custom thresholds override defaults per function call.<br>7. Items with individual stock policies alert on their specific thresholds; items without policy use 20 and 500.<br>8. Simulation daily reports reflect per-item thresholds accurately. |
| **Pass/fail criteria** | **Pass** if all listed pytest tests pass, lateness reference days are respected, ordering is descending, stock classifiers produce exact boundary results, and per-item policies govern alerts with 20/500 fallback; **Fail** if timing calculations fail, lists are unsorted, or policy thresholds are ignored. |
