### TC-SEC-02: Branch Protection, Secrets and Dependency Check

| Field | Content |
|---|---|
| TC ID | TC-SEC-02 |
| Title | `main` accepts only reviewed, CI-tested changes; the repository holds no secrets; the simulator has no network access and no runtime third-party dependencies |
| Requirement(s) | SCM-SR-005, SCM-SR-006 (security objective SCM-SO-2) |
| Type | Security (process) |
| Preconditions | 1. Tester is logged in to GitHub as the repository owner (`rohithkarning-debug`), who has admin rights, so that step 2 also checks that the rules apply to admins. 2. A local clone with `git checkout main && git pull origin main` done and a clean working tree. 3. A second team member is available for step 3. 4. The steps are run in Git Bash (or a Linux/macOS shell) from the repository root. |
| Test data | Throwaway local branch `sec-check`; one **empty** commit `test: direct push check (TC-SEC-02)`. Secret patterns: GitHub tokens (`ghp_…`, `github_pat_…`), AWS keys (`AKIA…`), private-key headers, and assignments to `api_key`, `secret`, `password`, `passwd`, `token`. No real credentials are used. |
| Objective | Prove that no one, including an admin, can change `main` without a pull request, a non-author approval and a passing `test` check, and that the code base exposes no secrets, network access or runtime dependencies. |
| Steps | 1. **Settings review:** open Settings → Branches → the rule for `main` and record each setting. 2. **Direct push (as admin):** `git checkout -b sec-check`; `git commit --allow-empty -m "test: direct push check (TC-SEC-02)"`; `git push origin sec-check:main`. Then `git push --force origin sec-check:main`. 3. **Merge without approval:** `git push -u origin sec-check`; open a pull request `sec-check` → `main`; wait for CI; try to merge without any review; try to approve as the author; ask a teammate to confirm the merge button state. Close the PR without merging and delete the remote and local `sec-check` branches. 4. **Secrets scan:** `git log --all -p \| grep -nEi "ghp_[A-Za-z0-9]{36}\|github_pat_\|AKIA[0-9A-Z]{16}\|BEGIN (RSA\|OPENSSH\|EC) PRIVATE KEY\|(api[_-]?key\|secret\|password\|passwd\|token)\s*[:=]"`; then check Security → Secret scanning alerts on GitHub. 5. **Network use:** `grep -rnE "socket\|urllib\|http\|requests" src/scm_sim/`. 6. **Dependencies:** `cat requirements.txt`; `grep -rhE "^\s*(from\|import) " src/scm_sim/*.py \| sort -u`. |
| Expected result | 1. The rule shows: *Require a pull request before merging* on, *Required approvals* = 1, *Dismiss stale pull request approvals when new commits are pushed* on, *Require status checks to pass* with required check `test`, *Require branches to be up to date before merging* on, *Do not allow bypassing the above settings* (rules apply to administrators) on, *Allow force pushes* off, *Allow deletions* off. 2. Both pushes are rejected by GitHub with a protected-branch error (e.g. `GH006: Protected branch update failed`), even though the tester is an admin; `main` on GitHub is unchanged. 3. The merge button is disabled with *Review required*; GitHub does not allow the author to approve their own PR; the PR is closed unmerged and the branch deleted. 4. The search prints nothing and GitHub shows no open secret-scanning alerts. 5. No matches: the simulator contains no network code. 6. `requirements.txt` lists only `pytest>=8.0` and `pytest-cov>=5.0` (test tools); `src/scm_sim/` imports only the standard library (`__future__`, `argparse`, `dataclasses`, `enum`, `random`, `typing`) and its own `scm_sim` modules. |
| Pass/fail criteria | **Pass** if all six expected results are observed. **Fail** if any branch-protection setting differs from step 1, any push in step 2 reaches `main`, a PR can be merged without a non-author approval and a green `test` check, any secret is found, or any network or third-party runtime import exists. If step 2 unexpectedly succeeds, record a High-severity defect and remove the empty commit from `main` through a reviewed PR. |
| Automated by | Not automated (manual process test). Steps 4–6 are read-only shell commands; steps 1–3 need GitHub admin access. |
| Actual result | Not run |
| Status | Not run |

**Pre-check (read-only, 11-10-2026, not a substitute for execution).** The public GitHub API for this repository reported `main` as `protected: true` with required status check `test` and `enforcement_level: everyone`, and all 20 CI runs up to run #20 succeeded. A dry run of the step 4–6 commands on commit `b3702ef` produced the expected output. Approval count, stale-review dismissal, the up-to-date rule, admin enforcement and the force-push and deletion settings can only be read when logged in, so steps 1–3 remain to be executed.
