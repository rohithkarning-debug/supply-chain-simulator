| **TC ID** | TC-REP-01 |
| **Title** | Seeded Reproducibility of Daily Reports and CLI Output |
| **Requirement(s)** | SCM-NF-002 |
| **Type** | Reliability |
| **Objective** | Verify that supplying the same random seed with the same scenario produces byte-for-byte identical daily reports and identical console output on every run, and that a different seed changes the simulated delays deterministically — so that any reported failure can be reproduced exactly from its seed. |
| **Preconditions** | The `scm_sim` package is importable and the demo scenario is available through `build_demo(seed)`. For the manual part, the repository root is the working directory and the command is run as `PYTHONPATH=src python -m scm_sim --days 10 --seed 42`. |
| **Test data** | Demo scenario built by `build_demo(seed=42)`: suppliers `SUP-RELIABLE` (reliability 1.0) and `SUP-FLAKY` (reliability 0.3); warehouses `WH-NORTH` (capacity 1200) and `WH-SOUTH` (capacity 500); SKUs `WIDGET`, `GADGET`, `GIZMO`; 14 customer orders including customer `C-ACME`. Seed 42 for the identity check; seed 7 for the variation check. |
| **Steps** | *Automated part.* 1. Build the demo with `build_demo(seed=42)` and call `run(10)`; keep the list of daily reports.<br>2. Build a second, independent demo with `build_demo(seed=42)` and call `run(10)`.<br>3. Compare the two lists of reports day by day.<br>*Manual part.* 4. Run `PYTHONPATH=src python -m scm_sim --days 10 --seed 42` twice, redirecting each run's full output to a separate file.<br>5. Compare the two output files, for example with `diff run1.txt run2.txt`.<br>6. Run `PYTHONPATH=src python -m scm_sim --days 10 --seed 7` and compare the delayed-shipment lines against the seed-42 output.<br>7. Record the host operating system and Python version used for the manual runs. |
| **Expected result** | 1. Ten reports are produced, one per simulated day.<br>2. Ten reports are produced from the second, independent instance.<br>3. The two lists are equal: every report for day *n* is identical in every key, including the `delayed_shipments` entries and their `days_late` values, the `stockouts`, `low_stock`, `excess` lists and the `orders` metrics.<br>4. Each run prints a day-by-day log and a final report and exits with code 0.<br>5. The two files are identical — `diff` reports no differences — on both the current host and, where repeated, on a different host.<br>6. The seed-7 run produces different shipment delays from the seed-42 run, and the difference is itself deterministic: repeating seed 7 reproduces the seed-7 output exactly.<br>7. The host details are recorded in the test report. |
| **Pass/fail criteria** | **Pass** if the automated test `test_same_seed_gives_identical_reports` passes, and if both seed-42 manual runs produce identical output while the seed-7 run produces different delays that are nonetheless repeatable. **Fail** if any value differs between two runs with the same seed, if any run raises an unhandled exception or exits with a non-zero code, if a different seed yields identical output to seed 42 across the whole run (which would indicate the seed is ignored), or if a change of host alters the output for a fixed seed. |
| **Automated by** | `tests/test_simulator.py::test_same_seed_gives_identical_reports` |
