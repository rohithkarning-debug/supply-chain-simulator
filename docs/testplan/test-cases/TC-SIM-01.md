### TC-SIM-01: Daily Step Order and Automatic Replenishment

| Field | Content |
|---|---|
| TC ID | TC-SIM-01 |
| Title | The daily step advances time, delivers shipments, fills existing back-orders before new demand, reorders exactly once per item, supports run summaries and CSV output, and trims reorders to warehouse capacity |
| Requirement(s) | SCM-F-041, SCM-F-042 |
| Type | Integration |
| Preconditions | 1. Python 3.11 virtual environment with `pip install -r requirements.txt` completed. 2. Repository at commit `b3702ef` (or a later green `main`). 3. Unless stated otherwise, each step uses a new scenario: `Simulation(seed=1)` with supplier `SUP` (lead time 2 days, reliability 1.0, so never delayed), warehouse `WH` with capacity 1000, and item (`WH`, `SKU`) with policy `StockPolicy(reorder_point, reorder_quantity, 500)` supplied by `SUP`. |
| Test data | Made-up IDs as used in the test code: supplier `SUP`, warehouse `WH`, SKU `SKU`, customers `C1`, `C2`. Defaults: initial stock 50, reorder point 20, reorder quantity 100. Step-specific values are given in each step. |
| Objective | Prove that `Simulation.step()` runs arrivals, retries existing back-orders before today's new demand, replenishes stock, and records the report in the required order; existing back-orders take priority over new orders; automatic replenishment is capacity-safe and exactly-once; and the CLI exposes working summary and CSV output. |
| Steps | 1. **Day counter:** with stock 50, read `day`; call `step()`; then `run(3)`; read `day` and the `day` of every report in `history`. 2. **Arrival after lead time:** with stock 100, `step()` (day 1); dispatch 40 units from `SUP` on day 1; `step()` (day 2) and read the level; `step()` (day 3) and read the shipment status, `actual_day` and level. 3. **Back-order priority:** with stock 30 and no automatic replenishment, schedule `C1` for 60 units on day 1 and step; schedule a day-2 shipment for 50 units and `C2` for 40 units; step on day 2; read `C1` and `C2` status, and stock. 4. **Replenishment fulfilment:** with stock 30, schedule `C1` for 60 units on day 1 and step; schedule `C2` for 15 units on day 2; step; step on day 3; step on day 4; read `ORD-0001` and stock after each step. 5. **Exactly one reorder:** with stock 10, `run(1)` three times, reading `shipments.in_transit()` and `logs[d].reorders`. 6. **Capacity trimming:** with warehouse capacity 50, policy `StockPolicy(20, 100, 50)` and stock 10, `run(3)`. 7. **CLI output:** run `scm-sim --days 3 --summary`, run `scm-sim --days 3 --csv metrics.csv`, and run both flags together. |
| Expected result | 1. `day` is 0 before stepping; after `step()` it is 1 and the report has `"day": 1`; after `run(3)` it is 4 and the history days are `[1, 2, 3, 4]`. 2. The shipment's `expected_day` is 3; on day 2 the level is still 100; on day 3 the status is `DELIVERED`, `actual_day == 3` and the level is 140. 3. Day 1: `ORD-0001` is `BACKORDERED`. Day 2: the arriving 50 units are used to fill existing `ORD-0001` first; the 40-unit `C2` order remains `BACKORDERED`; stock is 20. 4. Day 1: `ORD-0001` is `BACKORDERED`; day 2: the 15-unit order is fulfilled and one replenishment is in transit; day 3: `ORD-0001` remains back-ordered; day 4: stock arrives first, so `ORD-0001` is `FULFILLED` with `fulfilled_day == 4` and stock is 55. 5. Day 1: exactly 1 shipment is in transit and 1 reorder is logged; day 2: still 1 in transit and no new reorder; day 3: it arrives, leaving level 110 and 1 total reorder. 6. The reorder is trimmed to fit capacity, arrival does not raise `CapacityExceededError`, and the final level is 50. 7. `--summary` prints `Run Summary`; `--csv` creates a CSV with a header and one row per simulated day; combined flags produce both outputs. |
| Pass/fail criteria | **Pass** if every expected value is observed and all pytest tests listed below pass. **Fail** if the day counter or history is wrong, a shipment arrives early or late, an existing back-order is not prioritised over new demand, a back-order is not filled on the arrival day, a duplicate reorder is dispatched while one is in transit, CSV has the wrong shape, or any arrival raises `CapacityExceededError`. |
| Automated by | `tests/test_simulator.py::test_step_advances_day_counter`, `tests/test_simulator.py::test_shipment_arrives_after_lead_time_and_increases_stock`, `tests/test_simulator.py::test_large_order_is_backordered_then_fulfilled_after_replenishment`, `tests/test_simulator.py::test_low_stock_triggers_exactly_one_reorder_while_in_transit`, `tests/test_simulator.py::test_reorder_is_trimmed_to_fit_warehouse_capacity`, `tests/test_simulator.py::test_older_backorder_is_served_before_new_order_on_same_day`, `tests/test_simulator.py::test_cli_main_summary_flag` |
| Actual result | Pass (CI run #20, commit b3702ef) |
