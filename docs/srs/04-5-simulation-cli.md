### 4.5 Simulation Engine & CLI

**Description:** The Simulation Engine (`scm_sim.simulator`, class `Simulation`) wires the Inventory, Order Manager, Shipment Manager and Analytics components into one discrete, day-by-day simulation. The user (or the built-in `build_demo()` scenario) configures suppliers, warehouses, stock policies, initial stock and future customer demand. Each call to `step()` then advances the clock by exactly one day and runs a fixed sequence of events, automatically replenishing low stock and recording an analytics report. The CLI (`scm_sim.__main__`, function `main`) exposes the demo scenario as `python -m scm_sim --days N --seed S`.

**Priority:** High (simulation engine), Medium (CLI).

**Stimulus / response sequences**

| Stimulus | Response |
|---|---|
| Analyst adds suppliers, warehouses, policies, stock and scheduled orders | The scenario is stored at day 0; invalid references or values are rejected before anything is stored |
| Analyst or System timer calls `step()` | The day counter increases by 1 and the five daily events run in order; that day's report is returned and appended to `history` |
| Analyst calls `run(10)` | Ten steps run; a list of ten reports is returned |
| Evaluator runs `python -m scm_sim --days 10 --seed 42` | The demo prints a log for days 1–10 and the formatted final report, then exits with code 0 |

**Daily event order (one call to `step()`):**
1. Deliver shipments arriving today into inventory.
2. Create today's scheduled customer orders and try to fulfil each (otherwise back-order it).
3. Retry all open back-orders, oldest first.
4. Dispatch one replenishment per item that needs a reorder and has nothing already in transit, trimmed to warehouse capacity.
5. Build that day's analytics report and append it to the history.
