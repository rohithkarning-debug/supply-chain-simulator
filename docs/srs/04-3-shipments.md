### 4.3 Shipment and Supplier Management

Description: The Shipment and Supplier Management subsystem models external supplier entities, schedules and dispatches goods replenishments to network warehouses, simulates stochastic lead-time transit delays governed by supplier reliability metrics, receives completed shipments into warehouse inventory, and provides real-time querying for in-transit and overdue stock movements.

| SCM-F-021 | The system shall dispatch a replenishment shipment from a registered supplier to a designated warehouse for a given SKU and quantity (`quantity > 0`) on a specified simulation day (`day >= 0`), assigning sequential unique identifiers formatted as `SHP-0001`, `SHP-0002`, ..., computing the scheduled arrival day as `expected_day = day + supplier.lead_time_days`, setting initial status to `ShipmentStatus.IN_TRANSIT`, and shall raise a `KeyError` if `supplier_id` is unknown or a `ValueError` if `quantity <= 0` without mutating state. | Functional | High | Supply Chain Analyst / System timer | AC-SCM-F-021: Calling `ShipmentManager.dispatch()` creates a `Shipment` with status `IN_TRANSIT`, sets `expected_day = day + lead_time_days`, assigns sequential IDs matching `^SHP-\d{4}$`, raises `KeyError` when dispatched with an unknown supplier ID (e.g., `SUP-UNKNOWN`), and raises `ValueError` when `quantity <= 0`. Test: TC-SHP-01 | Component: `ShipmentManager.dispatch`, `Shipment` in `scm_sim.shipments`. Triggered during daily simulation step 4 (replenishment). Depends on SCM-F-020. |
| SCM-F-022 | The system shall model stochastic delivery delays during shipment dispatch such that if an explicit integer `delay` is provided, `arrival_day` is set to `expected_day + delay`; and if `delay` is `None`, a random draw from an injected `random.Random` instance is evaluated against `supplier.reliability`, assigning `delay = rng.randint(1, 3)` if `rng.random() > supplier.reliability` and `0` otherwise, guaranteeing that suppliers with `reliability == 1.0` are never delayed (`delay == 0`). | Functional | High | Supply Chain Analyst / Instructor | AC-SCM-F-022: When `delay=None` and `supplier.reliability == 1.0` (e.g., `SUP-RELIABLE`), `arrival_day` strictly equals `expected_day`; for suppliers with `reliability < 1.0` (e.g., `SUP-FLAKY`), delays of 1 to 3 days occur whenever `rng.random() > reliability`; passing an explicit `delay` value overrides random sampling deterministically. Test: TC-SHP-02 | Component: `ShipmentManager.dispatch` in `scm_sim.shipments`. Supports deterministic reproducibility via seeded PRNG (SCM-NF-002). |
| SCM-F-023 | The system shall, upon daily arrival processing (`process_arrivals(day)`), deliver every shipment in status `IN_TRANSIT` whose `arrival_day <= day` by incrementing warehouse stock via `inventory.add(warehouse_id, sku, quantity)`, transitioning status to `ShipmentStatus.DELIVERED`, and setting `actual_day = day`; and shall provide query methods `in_transit()` returning all active in-transit shipments and `delayed(current_day)` returning all shipments where `days_late(current_day) > 0`, where `days_late` evaluates to `max(0, actual_day - expected_day)` if delivered, or `max(0, current_day - expected_day)` if still in transit. | Functional | High | System timer / Supply Chain Analyst | AC-SCM-F-023: Calling `ShipmentManager.process_arrivals(day)` updates inventory stock solely via `inventory.add()`, updates status to `DELIVERED`, sets `actual_day = day`, and returns delivered shipments; shipments with `arrival_day > day` remain `IN_TRANSIT` with inventory unchanged; `delayed(current_day)` accurately flags both in-transit late and delivered late shipments. Test: TC-SHP-02 | Component: `ShipmentManager.process_arrivals`, `in_transit`, `delayed`, `Shipment.days_late` in `scm_sim.shipments`. Interacts with `Inventory.add` (SCM-F-001, SCM-F-002). |
